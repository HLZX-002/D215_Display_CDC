# 屏幕方向与 SN 管理

## 配置入口

运行现有 `sdk_me` / `me` / menuconfig，进入 `Display Parameter`。

1. 选择主板和屏型。
2. 新产品启用 `Use unified product orientation and SN (new products)`。
3. 在 `Product orientation` 中选择 A/B/C/D，默认 A。

方向定义：正对屏幕，画面相对面板原生基准顺时针旋转。

| 选择 | 角度 | 9.16 寸逻辑宽高 | 14.5 寸逻辑宽高 |
|---|---:|---|---|
| VMAXA | 0° | 462×1920 | 2560×720 |
| VMAXB | 90° | 1920×462 | 720×2560 |
| VMAXC | 180° | 462×1920 | 2560×720 |
| VMAXD | 270° | 1920×462 | 720×2560 |

面板时序保持基准宽高；90°/270°只交换应用的逻辑宽高。
不要直接编辑生成的 `.config`、`rtconfig.h` 或 `Kconfig.profiles`。

## 旧产品兼容

统一模式默认关闭。这是有意的升级保护：没有版本标记的旧配置，也会保持原有 SN、
framebuffer/LVGL 方向和触摸处理顺序，不能根据 SN 字母推断其是否使用新规则。
已有 `VMAXC` 的历史尺寸与方向语义继续由 `screen_sn_config.h` 的旧表处理。

升级旧设备时保留原 defconfig，并保持统一模式关闭。新旧模式之间的切换属于产品配置
变更，不能作为运行时旋转使用；回退旧产品应使用保存的旧 defconfig。

程序不会自动改写 Flash SN。新模式继续使用既有的严格前缀校验：旧 Flash SN 若与新产品
的型号、方向或宽高不符，不会作为新产品 SN 返回，而使用新配置的默认 SN；Flash 原始
内容仍保留。生产时需通过现有 SN 写入流程写入匹配新产品的完整 SN。

## 单一资料来源

`bsp/artinchip/drv/display/screen_profiles.json` 是新模式下屏幕几何和触摸校准的资料来源。
构建及 SDK menuconfig 入口会自动运行 `tools/scripts/screen_profiles.py`，只有内容变化
才更新生成文件。也可以手动执行：

```text
python tools/scripts/screen_profiles.py
python tools/scripts/screen_profiles.py --check
```

每条记录维护：

| 字段 | 含义 |
|---|---|
| `symbol` | 现有屏型选择符号，必须与 Kconfig 屏型对应 |
| `model` | 两位十进制 SN 型号编号 |
| `width` / `height` | 面板原生 0° 基准像素数，2～9999 |
| `touch_width` / `touch_height` | 控制器报文解析、协议轴交换之后的输入坐标像素数 |
| `touch_flip_x` / `touch_flip_y` | 在输入坐标系中应用的硬件镜像校准 |
| `touch_to_native_cw` | 镜像之后，从输入坐标系到面板原生坐标系的顺时针旋转 |

转换顺序固定为：输入限幅 → 硬件镜像 → 校准旋转 → 缩放至基准宽高 → 产品旋转的逆变换。
坐标范围使用 `0..宽-1`、`0..高-1`，避免右／下边缘产生越界。

9.16 寸、10.11 寸的输入坐标沿用旧配置的横向坐标系，使用 90° 校准转回原生竖向坐标系。
14.5 寸控制器报文中的轴交换仍在驱动内完成，资料表记录的是交换后的 2560×720。
6.67 寸沿用旧 SDK 的 1024×600 输入范围；19 寸与部分 12.6 寸沿用 2560×720 输入范围，
新模式统一缩放至对应面板基准尺寸。这些是对现有代码配置的迁移，不代替触摸模组的实机校准。

新增屏幕时，完成原有驱动、引脚、时序和屏型选择配置，再增加一条资料记录即可复用四个
产品方向。新模式的面板有效宽高也由该记录派生，不必再复制四套方向分支。

## 显示、触摸和运行时命令

- framebuffer 负责本地 UI 的最终旋转，独立 LVGL 旋转配置在新模式下关闭。
- USB 显示初始角度、framebuffer 角度、SN 方向都来自同一个产品方向；USB 全屏显示和
  UI 路径使用既有库接口，未修改预编译 USB 显示库。
- `aic_touch_transform()` 是控制器完成报文解析后的统一转换入口。兼容模式调用原有
  flip/rotate/scale/crop 顺序；新模式调用公共几何转换。
- 已接入 AXS15260、C145HAX01、C123HAX022、CST3240、GSL3676、GT911。新增触摸驱动需接入
  转换入口和范围报告，再扩展编译检查的支持列表；未接入的控制器会明确编译报错。
- 本地 UI 和 CDC 使用产品逻辑坐标。HID 运行时旋转在 HID 输出端处理，不修改驱动给本地
  UI 的坐标。HID 主机旋转仍使用绝对角度 0/90/180/270；居中裁剪也在该输出坐标系处理。
- 现有旋转命令和 SN 报文接口保留。应用临时旋转不修改 SN、Flash 或产品配置。

## SN 规则

```text
VMAX<方向字母><两位型号><四位逻辑宽>*<四位逻辑高>S<原有九位后缀>
```

例如：9.16 寸 A 的前缀为 `VMAXA160462*1920S`；B 为 `VMAXB161920*0462S`。
14.5 寸 D 的前缀为 `VMAXD590720*2560S`。

这里的“逻辑宽高”指产品配置方向的宽高，不随应用临时旋转改变。SN 仍为 26 字符，
Flash 存储布局、CDC 帧格式和九位后缀规则保持原有实现。

## 验证

```text
python tools/scripts/test_screen_orientation.py
python tools/scripts/test_screen_orientation.py --native
```

第一条使用 SDK 内置 kconfiglib 和 RISC-V 编译器，检查全部 16×4 配置、过期旋转选项、
原生时序宽高、USB 校准角度及 SN 的 C 编译约束。
第二条执行实际 C 转换，验证 64 个 SN 字符串、四角、旋转方向及负值／超范围输入。
Windows 原生 C 测试可使用 `CC` 指定编译器，或者安装 `ziglang`；固件构建不依赖它。
测试使用临时目录，不改写项目配置。

发布前需实机确认：9.16 寸与14.5 寸的四方向投屏、静态／视频启动画面、OSD、四角／多点
触摸、HID 运行时旋转与裁剪、CDC 触摸、SN 读写、重启和旧主机应用识别。尤其检查零度
基准与实际模组安装方向。软件编译及数学测试无法验证面板接线或预编译 USB 库的实际画面。
